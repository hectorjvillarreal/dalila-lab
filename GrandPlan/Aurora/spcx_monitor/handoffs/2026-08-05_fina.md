# SPCX → Fina handoff — 2026-08-05

## Why you're getting this

Your remit is cross-project coherence and cadence. The SPCX monitor — the one
Aurora artifact with a *daily* automated cadence — silently produced nothing
for 23 days, and the failure mode is generic to how Dalila runs automation. The
regime content went to Nina (`2026-08-05_nina.md`); this note is the
operational incident and its cadence lessons.

## The incident

- **Window:** 2026-07-13 → 2026-08-04, 23 days, no readings, no backfill.
- **Cause:** the dedicated sparse worktree (`/home/hectorjuan/Dalila-spcx`)
  that the daily systemd cycle renders from was removed — cleanly, via git —
  without disabling `spcx-render.timer`. Every subsequent run failed at
  `cd` with `ERROR: monitor dir missing`.
- **Why it stayed invisible:** the failure was *loud in the log and silent
  everywhere else*. `~/.spcx_render.log` recorded every failure (including
  `Persistent=true` catch-up runs on wake), but the timer unit stayed
  green/active, nothing alerted, and no one reads a log that no one is
  prompted to read. The series simply stopped accumulating.
- **Cost:** the blind window covered exactly the approach the 2026-06-19
  reading had flagged as the next regime event (the August unlock). The
  2026-08-05 restart classification jumped GREEN→AMBER on all three LIVE
  mechanisms at once — a step-change that an intact daily series would almost
  certainly have resolved into observable drift.

## The rebuild (2026-08-05, all committed to main)

1. Sparse worktree recreated, pinned to `main`, `spcx_monitor/` only.
2. Daily cycle re-run through the production path (`systemctl --user start
   spcx-render.service`) — clean: state file, macro fetch, render, commit,
   push.
3. Gap annotated in `state/2026-08-05.json` `analyst_note` — recorded as an
   outage, not a quiet market; nothing was backfilled.
4. Same-day classification pass (web-refreshed observables) → WATCH; Nina
   handoff filed; one-shot cloud reminder set for the 2026-08-06 unlock-day
   pass.

## Cadence lessons in your lane

1. **Paired-resource teardown.** The worktree and the timer are one unit;
   removing one without the other left a zombie cadence. Any Dalila automation
   whose runner depends on a filesystem/git resource should have its teardown
   documented as a single step (the monitor README's teardown section does
   list both — the removal didn't follow it).
2. **Silent-failure audit.** Worth a cadence sweep: which other standing
   automations (systemd timers, cron, routines) fail silent-green? A failure
   that only writes to its own log is unmonitored by construction. Even a
   crude weekly "did every timer's artifact actually change?" check would have
   caught this in week one, not week four.
3. **Gap semantics are now precedent.** The monitor's convention — no
   backfill, no fabricated continuity, outage annotated in the first
   post-restart reading, step-change explicitly attributed to the gap — is a
   reusable pattern for any interrupted Dalila time series (PROTO-RAG-001
   spirit: provenance over completeness).
4. **Pending formalisation flag, renewed.** `agent_handoff` remains
   non-protocol-codified; this is the third such note (06-19 Nina, 08-05
   Nina, this one). If the type is becoming load-bearing, it should graduate
   into PROTO-RAG-001 or a successor — your and Debb's call.
