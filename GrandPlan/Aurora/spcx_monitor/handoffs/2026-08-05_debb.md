## Failure mechanics (one line)

`git worktree remove /home/hectorjuan/Dalila-spcx` was run without
`systemctl --user disable --now spcx-render.timer`; the service then failed at
`cd` every run (`ERROR: monitor dir missing` in `~/.spcx_render.log`) while the
timer unit itself stayed `active (waiting)` — systemd considers a timer healthy
if it *fires*, regardless of what the service exit status was.

## Hardening options (in rough order of value)

1. **Make the service fail loudly.** The wrapper (`~/.local/bin/spcx_render.sh`)
   exits 1 on the missing dir, but nothing consumes that failure. Options:
   - `OnFailure=spcx-render-alert.service` on the unit — a tiny oneshot that
     drops a dated marker file somewhere visible (e.g.
     `~/Dalila/GrandPlan/Aurora/spcx_monitor/AUTOMATION_FAILED.md` on the
     working branch) or fires `notify-send`. A failure that writes into the
     *repo* gets seen; one that writes to `~/.spcx_render.log` does not.
   - Alternatively `ExecStartPre=/usr/bin/test -d /home/hectorjuan/Dalila-spcx`
     so the unit records `failed` state distinctly before the wrapper runs.
2. **Self-healing worktree.** The wrapper could recreate the worktree when
   missing (`git -C ~/Dalila worktree add --no-checkout … && sparse-checkout
   set …`) instead of dying. Today's manual rebuild is exactly this sequence;
   it is idempotent and safe to automate. Trade-off: it papers over an
   intentional teardown — pair it with the alert so recreation is *noticed*.
3. **Atomic teardown script.** The README's teardown section lists all five
   steps in the right order, but the incident shows prose checklists don't
   bind. A `spcx_teardown.sh` next to the wrapper (disable timer → remove
   units → daemon-reload → worktree remove → rm wrapper) makes the pairing
   mechanical. Generic pattern for any Dalila automation with a paired
   filesystem resource.
4. **Staleness tripwire in the artifact itself.** `render` could stamp the
   dashboard with "generated N days after the latest state file" and flag
   N > 2 visually — then the artifact, which *is* looked at, carries its own
   freshness alarm. Cheap: it's stdlib date arithmetic in `spcx_monitor.py`.
5. **Knowledge-base entry.** The silent-green timer failure mode
   (timer-healthy ≠ service-succeeding) is generic to every systemd user timer
   on Dalila. Wherever your infra notes live, it deserves a line; the
   incident's full forensics are reconstructible from `~/.spcx_render.log`
   plus the commits cited in the Fina note.
